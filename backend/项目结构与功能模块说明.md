# Shopro 管理后台：项目结构与功能模块说明

## 1. 项目定位

本仓库当前实现的是 **Shopro AI 厂商运营后台前端**。它采用 Vue 3 构建，可在演示模式下通过 MSW 在浏览器中模拟 `/api/admin/**` 接口，也可切换为调用实际的 Spring Boot 或其他兼容 REST 服务。

> 仓库名称虽为 `Shopro-backend`，但当前可运行代码主体为管理后台前端；后端通过统一 API 契约接入，并不包含在本仓库的 `src/` 中。

主要技术栈：Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、Axios、ECharts、Day.js、MSW 与 pnpm。

## 2. 运行与构建

| 命令 | 用途 |
| --- | --- |
| `pnpm install` | 安装项目依赖 |
| `pnpm dev` | 启动本地开发服务 |
| `pnpm build` | 类型检查并构建生产产物 |
| `pnpm preview` | 本地预览构建后的 `dist/` |

环境变量定义见 `.env.example`：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_USE_MOCK` | `true` | 是否启用 MSW 浏览器模拟接口 |
| `VITE_API_BASE_URL` | `/api` | 实际接口基础地址 |
| `VITE_APP_MODE` | `demo` | 运行模式；生产模式下不启动模拟服务 |

演示登录账号为 `admin@shopro.ai`，密码可任意填写。

## 3. 总体架构

```text
浏览器
  └─ Vue Router：登录校验、权限路由守卫、懒加载页面
       └─ AdminLayout：固定左侧导航 + 顶部栏 + 右侧独立滚动内容区
            └─ 业务页面（views）
                 └─ API 模块（api）
                      └─ Axios 请求客户端
                           ├─ MSW Mock（演示模式）
                           └─ /api/admin/**（实际后端模式）
```

- 路由按页面动态导入，非当前访问页面不会进入初始页面代码。
- `auth` Pinia Store 持有管理员信息和权限集合，并同步到浏览器本地存储。
- API 统一使用 `{ code, message, data, traceId? }` 响应结构；列表接口的数据结构为 `{ items, total, page, pageSize }`。
- Mock 层按“数据、领域规则、接口处理器、初始场景”划分，方便与真实后端接口逐步替换。

## 4. 目录结构

```text
Shopro-backend/
├─ src/
│  ├─ api/                 # 后台 REST API 封装与请求客户端
│  ├─ components/
│  │  ├─ common/           # 通用页面头、状态标签、空状态、确认弹窗
│  │  └─ business/         # 积分调整、风险处置、工作流时间线等业务组件
│  ├─ composables/         # 可复用组合式逻辑，例如分页查询
│  ├─ constants/           # 权限与固定枚举常量
│  ├─ layouts/             # 管理后台整体布局和导航
│  ├─ mocks/               # MSW 数据库、种子数据、领域规则与接口处理器
│  ├─ router/              # 路由声明、鉴权与权限守卫
│  ├─ stores/              # Pinia 状态；当前包含管理员认证状态
│  ├─ types/               # 领域模型、接口响应和请求参数类型
│  ├─ views/               # 页面级组件，按业务域划分
│  ├─ App.vue              # 应用根组件
│  ├─ main.ts              # 应用启动、Element Plus 组件注册、Mock 启动
│  └─ style.css            # 全局样式和后台布局规则
├─ public/                 # 静态文件和 MSW Worker
├─ docs/                   # 整改方案、目标模型与执行任务书
├─ dist/                   # 构建产物（自动生成）
├─ vite.config.ts          # Vite 配置与第三方依赖分包策略
├─ package.json            # 依赖与脚本定义
└─ .env.example            # 环境变量示例
```

## 5. 页面、路由与权限

| 功能域 | 主要路由 | 所需权限 | 页面职责 |
| --- | --- | --- | --- |
| 登录 | `/login` | 无 | 管理员登录并写入会话信息 |
| 运营总览 | `/dashboard` | `dashboard:view` | 核心指标、履约趋势、任务分布、待办跳转 |
| 用户与积分 | `/users`、`/customers/users/:id` | `customers:view` | 用户查询、详情、能力配置、积分流水与调整 |
| 客服工单 | `/tickets`、`/tickets/:id` | `customers:view` | 工单列表、创建、查看和状态更新 |
| AI 任务中心 | `/ai-operations`、`/ai-operations/workflows/:id` | `workflow:view` | 工作流与任务查询、尝试记录、重试、取消、人工退款、服务健康 |
| 风险与内容治理 | `/risk/events`、`/risk/events/:id` | `risk:view` | 风险事件查询、证据查看、处置决定和申诉处理 |
| 订单与套餐 | `/billing/orders`、`/billing/orders/:id` | `billing:view` | 订单、权益补发、退款流程、积分流水、套餐版本 |
| 系统运营 | `/system` | `system:view` | 服务健康、管理员与角色、审批、审计日志、演示数据恢复 |

路由守卫会阻止未登录访问；若登录用户缺少目标页面权限，则自动回到运营总览。左侧导航同样按权限过滤，因此不会展示不可访问的入口。

## 6. 功能模块说明

### 6.1 运营工作台

- 支持按日期范围查看 AI 履约成功率、净支付金额、风险待办和服务影响等指标，并显示环比基准。
- 使用折线图展示履约趋势、环形图展示任务状态分布；图表会在刷新时复用实例，在页面卸载时销毁。
- 待办项包含工作流、交易计费、风险治理和服务健康分类，可直接进入已筛选的处置页面。

### 6.2 客户、积分与工单

- 用户列表支持分页、筛选和详情查看；详情页可查看组织、能力与使用信息。
- 积分模块提供用户维度积分流水和人工调整入口，并保存调整原因及操作结果。
- 工单模块覆盖工单创建、列表查询、详情查看、状态/处理信息更新。

### 6.3 AI 任务运营

- 工作流列表显示任务状态、调用方、时间和风险/失败等筛选信息。
- 工作流详情呈现任务、尝试记录、资源或积分影响及服务商健康状态。
- 管理员可执行任务重试、取消请求和失败任务人工退款；具体状态校验由接口（演示时由 Mock 领域规则）负责。

### 6.4 风险与内容治理

- 风险事件支持按状态、等级和时间查询，详情中展示事件上下文、证据与历史记录。
- 风险处置通过专用弹窗提交决定与原因，支持申诉信息登记。
- 风险动作保留可审计的操作痕迹，避免仅在页面侧更改展示状态。

### 6.5 订单、退款与套餐

- 订单列表和详情用于查看支付、权益和关联信息。
- 对权益异常订单可重新发放权益；退款支持发起、审批和驳回流程。
- 计费域同时提供总积分流水查询与套餐快照/版本创建能力。

### 6.6 系统运营与治理

- 汇总服务健康状态、管理员、角色权限和审批请求。
- 支持按条件查询审计日志，并提供全局搜索入口。
- 演示模式下可恢复初始演示数据，便于重复验证流程。

## 7. API 与 Mock 对接约定

API 文件与接口域一一对应，例如 `src/api/workflows.ts` 对应 `/api/admin/ai/**`，`src/api/billing.ts` 对应 `/api/admin/billing/**`。

接入真实后端时：

1. 设置 `VITE_USE_MOCK=false`。
2. 将 `VITE_API_BASE_URL` 配置为目标后端地址。
3. 保持现有接口路径、响应外层结构和分页结构不变。
4. 由后端负责 JWT、RBAC、状态机校验、审计持久化与交易一致性；前端继续负责页面交互、权限展示和错误提示。

MSW 的数据保存在浏览器本地存储。`src/mocks/domain/` 中的规则文件用于模拟权限、积分、任务、风险、工单和计费等领域约束，不应被视为生产后端实现。

## 8. 前端实现约定

- 新增领域接口时，先补充 `types/` 中的类型，再在对应 `api/` 文件中封装请求，最后接入页面。
- 新页面须在 `router/index.ts` 中以懒加载方式注册，并配置最小必要权限。
- 可复用的无业务组件放入 `components/common/`；涉及领域动作的弹窗或时间线放入 `components/business/`。
- 页面内容在右侧 `el-main` 区域独立滚动，左侧导航及顶部栏固定在应用壳中。
- ECharts 仅按页面需要注册图表与渲染器；Element Plus 使用精确组件入口，避免重新引入完整组件库。

## 9. 构建与部署

`pnpm build` 会先执行 TypeScript 类型检查，再生成 `dist/` 静态资源。构建配置会将 Vue、Element Plus、ECharts、MSW 和工具依赖划分为稳定的独立分包，以降低页面间重复加载。

部署时可将 `dist/` 发布到静态托管服务，或复制至 Spring Boot 的 `src/main/resources/static`。若由后端提供前端资源，需要同时配置单页应用历史路由回退，确保直接访问业务 URL 时仍返回应用入口页。
