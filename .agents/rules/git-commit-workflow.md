# Git 变更管理与提交规范

## 触发时机
- **文件修改触发**：当对话交互中首次包含文件新增、修改或删除操作完成时；
- **用户主动要求**：当用户明确提出提交、推送到仓库或执行 Git 变更管理时。

## 执行流程与规范
当达到触发条件时，必须按顺序统一执行以下 Git 变更管理步骤：

1. **变更暂存**：
   - 执行 `git add .` 将本次所有修改及新增文件加入暂存区。

2. **提交记录规范**：
   - 执行 `git commit -m "<中文详细提交描述>"`。
   - 提交描述规范：必须使用**简明、专业、清晰的中文**，系统性概括本轮累计修改的核心内容与变更点（例如：明确指出修改的模块、新增的功能特性或修复的缺陷，避免使用“更新代码”、“update”等模糊词汇）。

3. **同步远程仓库**：
   - 执行 `git push`（或确认远程分支状态）将变更同步至对应远程分支。

4. **异常与确认机制**：
   - 若当前分支未建立远程上游关联、推送遇到冲突或推送前需要用户确认，立即向用户清晰汇报当前 Git 状态（包括本地提交信息、远程分支状态及待解决问题）。
